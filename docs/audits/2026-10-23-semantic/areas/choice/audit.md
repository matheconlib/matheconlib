## Associated relationship checks

- `Conditions.lean:87–121` correctly identifies substitutability with monotone rejection and Chernoff contraction. The contraposition is restricted to available elements before collapsing inserted menus, so it does not assert that unavailable elements are rejected.
- `Conditions.lean:338–358` uses finite menus precisely where equal finite cardinalities force equal nested chosen sets. `Conditions.lean:360–393` correctly derives substitutes and finite-menu LAD from consistency plus unit demand, allowing refusal to choose. `Conditions.lean:395–452` gives both directions of path independence versus substitutes plus IRC without finiteness.
- `SubstituteHull.lean:149–180` preserves IRC without an implicit compactness assumption: if `H(Y) ⊆ Z ⊆ Y` and `x ∈ H(Z)` has witness `W ⊇ Z`, every choice from `W ∪ Y` that lies in `Y` belongs to `H(Y) ⊆ Z ⊆ W`; choices outside `Y` already lie in `W`. Thus `C(W ∪ Y) ⊆ W`, and IRC gives `C(W ∪ Y)=C(W)`. This supplies the witness for `x ∈ H(Y)`; hereditary contraction gives the reverse inclusion. This argument works for arbitrary sets.
- `SubstituteHull.lean:260–442` keeps every strict repair below every substitutable upper bound and above its predecessor. Terminal finite runs therefore equal the hull. An infinite-carrier finite run is not promised to terminate; finite-carrier termination follows from strict increase in a finite set of choice rules. Selector convergence explicitly requires an effective repair at every nonterminal step.
- `Matching/Relationships.lean` does not confuse completion with enlargement. The arbitrary-type converse explicitly assumes a pointwise enlarging completion; forward hull-completion equivalences require IRC, counterparty feasibility and finite-valuedness. The pivotal finite argument is on the finite choice from the larger menu, not on an unassumed finite menu. Preference corollaries retain finite-contract assumptions when extracting IRC from maximization.

## Hostile candidates and scope boundaries

The following were considered and rejected as defects after checking the source contracts.

1. Empty choices are allowed in matching choice theory and in the declared contracting-map interface; no nonempty-valued classical choice convention is advertised (`Basic.lean:12–14,42–48`).
2. Arbitrary-superset substitutes is stronger than the printed single-addition condition on infinite carriers, but the distinction is prominently explicit (`Conditions.lean:60–65`). The existing analytic/Lean witness is `infiniteOrEmpty` on ℕ in `MathEconLibTest/Choice/Counterexamples.lean:42–161`; it is a boundary example rather than a new finding.
3. LAD concerns finite menus only, avoiding the meaningless use of `Set.ncard = 0` on infinite outputs. It must not be quoted as an arbitrary-cardinality demand theorem (`Conditions.lean:201–218`).
4. Infinite preference menus need not attain a greatest bundle. For the fully explicit order `r(none)=0`, `r(some n)=n+1` on ℕ options, choice at all ℕ is empty but choice at `{0}` is `{0}`. The derivation independently checks every option is beaten on the infinite menu and `some 0` is best on the singleton. This disproves infinite IRC for the constructor, but the source explicitly uses an empty fallback and states IRC only for finite menus/types (`Induced.lean:35–37,60–64,393–403`). It is not a defect.
5. `LinearOrder` excludes indifference, and mapping excludes new alternatives. Both restrictions are part of the named input/interface. General weak preferences would require a different bundle-choice correspondence; simply unioning distinct tied bundles could violate the represented bundle feasibility restriction.
6. Ordinary completion permits non-enlarging choices and bare completability omits IRC. Those are explicit choices matching Zhang2016's displayed formula; the library exposes the stronger joint-IRC existence predicate needed in stability results.

No suspected substantive defect remains, so there is no reportable counterexample/correction pair to submit for independent defect verification.
