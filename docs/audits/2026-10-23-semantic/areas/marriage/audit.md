## Scope and standard concepts

The inventory contains 81 definition-like declarations in eight files. Definition-free theorem/interface files were also inspected for the assumptions they advertise. The stable lattice instance at `StableOrder.lean:88` and decidability instance at `Basic.lean:360` were additionally checked although absent from the definition inventory.

The benchmark is the standard strict-preference one-to-one marriage model with outside options and potentially incomplete acceptable lists. The source allows unequal or empty populations. Preferences below the outside option are economically irrelevant to stable matchings. [Gale and Shapley (1962), §§2–5](https://www.math.utoronto.ca/mccann/assignments/477/GaleShapley62.pdf) specifies strict rankings, permits unacceptable alternatives, defines mutually beneficial blocking, and defines a side's optimum relative to every stable assignment. The formal predicates match these concepts on their declared domain.

## Bidirectional reasoning for the basic economic predicates

1. A `PEquiv` is precisely a bipartite partial matching: its two optional partner maps are inverse on every matched pair. Conversely, a relation with at most one edge in every row and column determines such partner maps. `graphOf` retains exactly those edges. The supporting graph/reconstruction API was read at `ForMathlib/Data/PartialMatching.lean:28–178`; the foundations audit owns that file.
2. Every supplied `LinearOrder (Option partner)` is a strict complete/transitive preference with an outside option. Conversely, such a strict ranking supplies that order (classical decidability is enough for the noncomputable model). The conventions explicitly make the second argument of `ltM`/`leM` the better option. Nothing assumes `none` is globally worst.
3. For a matched man, `none ≤ some w` is equivalent to `none < some w`, since the options are unequal. Thus formal IR exactly excludes unacceptable assigned partners; unmatched agents compare `none` with itself and satisfy IR. The same proof applies to women. The universal and two-side conjunctions are exact.
4. A formal blocking pair satisfies the two strict improvements of the standard definition. A pair already in the matching cannot block, since a strict order is irreflexive, so no separate nonmembership clause is needed. On an IR matching, `none ≤ current < other` also proves the proposed counterpart is acceptable; an explicit acceptability conjunct would be redundant. Conversely, every standard blocking pair satisfies those comparisons. The duplicate universal side formulations in `Unblocked` quantify exactly the same pairs; `Basic.lean:101–124` proves each equivalent to one copy.
5. Formal stability is IR plus the absence of such pairs, proving equivalence in both directions. The four optimal/pessimal predicates each require stability and quantify over *all* stable alternatives. Hence an unstable object cannot be a vacuous optimum, and the predicates express greatest/least partner assignments rather than merely Pareto-undominated stable outcomes.
6. Induced unit-demand choice exactly maximizes own optional partners whenever a maximum exists. Finite menus always have a maximum because `none` is included. Infinite menus with no greatest acceptable partner deliberately yield empty choice; this is documented at `Preferences.lean:18–22`. IRC and finite existence/algorithm/lattice results do not use that extension without the required finite hypotheses.

## Rejected alarms and explicit boundary cases

These are not findings. They record attempts to refute the definitions and the precise reason each attempt fails.

- **Tie exclusion:** one man and one woman indifferent between each other and single can have stability variants with ties. The data type explicitly demands `LinearOrder`; this is outside the stated strict-preference domain, so it is not a false negative within that domain. Supporting ties would require weak-order data and explicit weak/strong/super-stability APIs, a model extension.
- **Unacceptable partners:** in a one-man/one-woman market with `some w < none` for the man, maximizing a menu containing the pair returns `none`; IR forbids assigning it. Putting `none` in every menu prevents the tempting false-positive proposal.
- **Already-matched “blocking” pair:** if `μ m = some w`, inverse consistency gives `μ.symm w = some m`; both purported improvements reduce to `x < x`. Thus omission of an explicit `μ m ≠ some w` condition adds no false positives.
- **Arbitrary terminal histories:** let both members of a one-pair market prefer each other to single and take `R = {(m,w)}`. The recurrence is terminal and `gsMatchingAt R` is empty, hence not stable. This does not refute a declaration: `gsMatchingAt` promises a partial matching for arbitrary terminal input; its stability theorem at `DeferredAcceptance.lean:276–278` additionally requires `R = gsRejected n`, and this R is never reached from empty.
- **Unbounded acceptable menu:** one man with women indexed by naturals, ordered `none < some 0 < some 1 < …`, has no greatest optional partner in the full menu. The induced choice is empty. The source explicitly documents this extension and withholds global IRC. Finite constructions cannot instantiate this population as `Fintype`. Reporting it as a finite marriage or maximum-selection defect would ignore the stated domain.
- **Algorithm names versus endpoints:** `deferredAcceptance` and its woman-proposing analogue explicitly say they are endpoint specifications (`FixedPointConvergence.lean:61–67,140–146`); actual rejection updates and executable procedures are separately defined. No tautologically defined endpoint is advertised as executable.
- **Round alignment and fuel:** generalized contracts iteration and classical proposal rounds need not agree at the same n. The source claims eventual endpoint agreement, not equal intermediate states. The user-fuel function explicitly permits early stopping and no stability conclusion is attached to insufficient fuel.
- **Economic order versus matching extension:** stable matchings have a dedicated carrier/order with top man-optimal and bottom woman-optimal. Bare `PEquiv` retains its extension order, so a universal comparison of bare partial matchings is not silently reinterpreted as preference.

No proposed source correction is needed for a verified substantive defect in this area. The finite-menu and strict-order boundaries above should remain explicit if the APIs are extended.
