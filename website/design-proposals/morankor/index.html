MathEconLib

Machine-checked mathematical economics.

MathEconLib is the home of auctionlib, a formalization of auction theory and mechanism design in the Lean 4 proof assistant, and of the further libraries that will follow it.

A machine-checked theorem is one whose statement and proof have been verified by a small, trusted kernel. There is no step the reader has to take on faith and no hypothesis that can go unstated: if the proof compiles, the theorem holds exactly as written. For economic theory, where results are reused across many papers with slightly different assumptions, that precision is the point. The library records the exact conditions under which the envelope theorem, Myerson's lemma, or revenue equivalence hold, and any downstream result inherits them automatically.

Everything is built on Mathlib, the community library of formal mathematics, so probability, measure theory, and analysis come from the same source the rest of the formal-mathematics world uses. The project is developed with Axiom Math. [One sentence on the role of AI-assisted formalization in the project, to confirm.]

This site is the stable place to point people at, a home for the documentation, and a record of who works on what. Development happens on GitHub.

auctionlib

The first library. It formalizes the single-parameter theory of auctions and pricing, from incentive compatibility through revenue equivalence, together with the game-theoretic foundations those results assume. The repository is currently private; [maintainer] grants access.

The library keeps apart three things that textbooks usually blend:

  1. Mechanism nthe rules of the game: an allocation rule x and a payment rule t over the vector of reports
  2. add random types for each bidder on a probability space (Ω, ℙ)
  3. Auction Ω na mechanism inside its probabilistic environment
  4. fix one bidder and the strategy the others play
  5. BidderProblemthat bidder's interim decision problem: win probability, cost, strategy

A BidderProblem is a special case of a SingleParameterProblem, which covers any quasilinear problem with payoff u(v,a) = v·x(a) − t(a), whether the action is a bid, a report, a contract choice, or a purchase decision. The envelope theorem and the payment identity are proved once at that level and reused by every application.

The README indexes every file and theorem and is the authoritative list; this page shows only the headline results.

Every result compiles without sorry, and #print axioms on the main theorems shows only propext, Classical.choice, and Quot.sound. The statements of the core theorems are pinned in a separate file that the build checks, so a change to any public statement breaks the build loudly rather than silently.

Contributing

New theorems in existing chapters, documentation, and applications built on the existing layers can go straight to a pull request. Results destined for Mathlib, kept in the ForMathlib folder, are a good first contribution.

Changes to the foundational layers start with a design issue: sketch the definitions and main statements and get agreement on the shape before writing proofs. Every pull request must build cleanly, contain no sorry, admit, or native_decide, and add no axioms beyond the standard three.

The full rules are in CONTRIBUTING.md. Questions go to the person listed under People, or [discussion venue, e.g. a Zulip stream or GitHub Discussions].
